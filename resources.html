How remote-first teams actually work

Read how the best distributed teams write

The Done / Doing / Blocked update (copy it)

Update, [day] — [project] Done: [what finished, with the file name, link, or number] Doing: [what's next] — done by [day, time, time zone] Blocked: [what you need, from whom] (or: nothing) Where it lives: [folder / repo / channel]

Weekly summary, [Friday date] Three things done: 1. 2. 3. One thing I learned: One thing I need from you: Next week's first task:

No Slack or repo? Post it in a Teams channel, a shared Google Doc, or a plain email with the subject “Update, Monday”.

The remote day

WhenMove
9:00Post Done / Doing / Blocked. Set your status. Block deep-work hours.
9:30Deep work: notifications off, one task, two hours.
11:30Check-in: reply to everything; send batched questions in one numbered message.
5:00Handoff line in the channel: what's done, where it lives, what happens tomorrow.
Friday150-word summary to your manager: three done, one learned, one needed.

The fix for every remote risk has the same shape: write it down before anyone has to ask.
